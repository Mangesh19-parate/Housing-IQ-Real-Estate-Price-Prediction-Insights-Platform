# Implementation Plan — Step 01: Repo Scaffolding And Environment Setup

## Context

The HousingIQ scaffold was generated by `scaffold.ps1` on Day 0. Every Python, HTML, CSS, and JS file under `app/`, `api/`, `tests/` is currently a **0-byte stub**. `requirements.txt`, `CLAUDE.md`, and all 11 docs (`docs/01-..11-*.md`) are already in place. The dataset (`data/raw/`, ~101 MB across 4 CSVs + facet lookups) is committed. `.gitignore` exists but lacks the runtime artifacts this spec needs.

The goal of Step 01 (per `01-repo-scaffolding-and-environment-setup.md` and `06-IMPLEMENTATION-PLAN.md` Day 1) is to turn that empty scaffold into a **working two-service dev loop** (Flask `:5000` + FastAPI `:8000`) with:

- Configurable SQLite app DB (4 operational tables: `prediction_log`, `recommendation_log`, `classification_log`, `model_registry`) — initialized on demand, no model loading.
- A real landing page (Flask `GET /`) and `GET /health` (FastAPI).
- A runnable `scripts/run_pipeline.py` entry stub that later specs extend.
- `pytest` + `ruff` wired to the new code.
- `.env.example` documenting every env var the runtime uses.

No new pip packages. Everything needed is already pinned in `requirements.txt`.

This is the foundation every later spec depends on (cleaning, training, recommenders, insights, UI). All routes other than `GET /` and `GET /health` remain stubs — they belong to specs 02+.

## Recommended approach

The work splits cleanly into six sequenced commits-worth of diff. Each is small and independently testable.

### Phase A — Package surfaces (5 minutes)

Create empty `__init__.py` files at every package boundary so `python -m app.app` and `uvicorn api.main:app` work without `PYTHONPATH` games. Per the spec's "Files to create" section, the full list:

- `app/__init__.py`, `app/database/__init__.py`
- `api/__init__.py`, `api/routers/__init__.py`, `api/schemas/__init__.py`, `api/services/__init__.py`
- `ml/__init__.py`, `ml/cleaning/__init__.py`, `ml/features/__init__.py`, `ml/training/__init__.py`, `ml/evaluation/__init__.py`, `ml/recommender/__init__.py`
- `tests/__init__.py`

**Verify:** `python -c "import app, api, ml"` returns 0 from repo root.

### Phase B — Config + DB layer

Per spec, create `app/config.py` and `api/config.py` next to each other so Flask and FastAPI read the same env keys with no drift:

- `app/config.py` — exports `APP_DB_PATH`, `FLASK_DEBUG`, `FASTAPI_BASE_URL`, `FLASK_SECRET_KEY`. Reads via `python-dotenv`'s `load_dotenv()` at import time. Defaults: `data/app.db`, `False`, `http://localhost:8000`, a dev-only secret string (not a real secret — this app has no auth).
- `api/config.py` — `MODELS_DIR`, `ANALYTICS_CACHE_DIR`, `PROCESSED_DATA_DIR`, `APP_DB_PATH`. Same loader. Defaults from CLAUDE.md's directory layout.

**Hard rule:** both files import nothing from each other; both are pure stdlib + `python-dotenv`. No Flask- or FastAPI-specific code lives here. This keeps the config importable from any future location (scripts, tests, notebooks).

Create `app/database/db.py`:

- Top-level constants for the four table DDL strings, derived from the corrected schema above.
- `get_db()` — `@contextmanager` that yields a `sqlite3.Connection` with `row_factory = sqlite3.Row`. Caller is responsible for committing; the context manager only commits if no exception, otherwise rolls back. Opens (and ensures `data/` exists via `os.makedirs`) the file at `APP_DB_PATH`.
- `init_db(db_path=None)` — opens a connection, executes all four `CREATE TABLE IF NOT EXISTS` statements. `db_path` arg overrides the env var when tests need a temp file.
- All SQL is parameterized (`?` placeholders). Per CLAUDE.md and 08-RULES §1, no f-strings or `.format()` into queries, ever.

The `git_commit` column in `model_registry` will be populated by future training scripts, but the schema must include it now so we don't migrate later.

### Phase C — Make Flask a real app

Replace the 0-byte `app/app.py` with:

- `create_app() -> flask.Flask` factory (CLAUDE.md implies this pattern; spec expects it via `test_app_imports`).
- Reads `app.config["SECRET_KEY"]` from `app/config.py`.
- Registers `GET /` that renders `landing.html`.
- Registers a `before_request` hook that calls `init_db()` once per process — cheap, idempotent, gives every test session a clean DB on first hit.
- Registers a Flask error handler that uses `abort()` (per CLAUDE.md error-handling rule; later specs add real error pages, this just makes 404/500 work).
- Bottom-level `if __name__ == "__main__": app.run(host="0.0.0.0", port=5000, debug=FLASK_DEBUG)` so `python -m app.app` works.

Create `app/templates/base.html` — minimal: `<!doctype html>`, `<head>` with `<link rel="stylesheet" href="{{ url_for('static', filename='css/style.css') }}">`, `<body>` with `{% block content %}{% endblock %}`.

Create `app/templates/landing.html` — extends `base.html`, has:

- `<h1>HousingIQ</h1>` heading text (the assertion in `test_flask_landing_renders`).
- 4 city buttons (Gurgaon, Hyderabad, Kolkata, Mumbai), each a `<button data-city="...">` — no JS wired yet, just the markup.
- 6 module `<a>` cards linking to `/predict`, `/classify`, `/analytics`, `/recommend`, `/insights`, `/map`. All use `url_for()` per CLAUDE.md.
- No hardcoded hex — every color comes from `var(--color-...)`.

Create `app/static/css/style.css` — `:root { --color-bg, --color-fg, --color-accent, --space-1..4, --radius, --font-sans }` + a 4-line reset. Heavier styling arrives in a later `ui-ux` spec.

### Phase D — Make FastAPI a real app

Replace `api/main.py` 0-byte stub with:

- `app = FastAPI(title="HousingIQ Inference", version="0.0.1")`
- `app.include_router(...)` for each of the 5 still-stub routers so the package imports cleanly later.
- `@app.on_event("startup")` calls `init_db()` once.
- `@app.get("/health")` returns `{"status": "ok"}`. (Decision recorded: no DB ping — pure liveness, no model loading, no log writes.)

Router files (`predict.py`, `classify.py`, `analytics.py`, `recommend.py`, `insights.py`) stay empty 0-byte files for now. The package needs them to exist so `include_router` lines don't break; later specs fill them.

### Phase E — Test scaffold + pipeline stub + .env.example

**Create `tests/conftest.py` with 3 fixtures:**

- `tmp_clean_db(tmp_path, monkeypatch)` — sets `APP_DB_PATH` to a `tmp_path / "app.db"`, calls `init_db()`, yields the path. Tears down by deleting the file.
- `app_client(tmp_clean_db)` — returns `app.create_app().test_client()` against the temp DB.
- `api_client()` — returns `fastapi.testclient.TestClient(api.main.app)`. No DB needed since `/health` doesn't touch the DB.

**Create `tests/test_scaffolding.py`** — exactly the 11 smoke tests called out in the spec's "Definition of done" §1:

1. `test_app_imports` — `from app.app import create_app; create_app()`.
2. `test_api_imports` — `from api.main import app`.
3. `test_flask_landing_renders` — GET `/` via `app_client` returns 200 and body contains `"HousingIQ"`.
4. `test_flask_landing_extends_base` — read `app/templates/landing.html` source, assert startswith `{% extends "base.html" %}`.
5. `test_fastapi_health` — GET `/health` returns 200 + `{"status": "ok"}`.
6. `test_init_db_creates_tables` — call `init_db()` on temp DB, query `sqlite_master`, assert 4 expected names present.
7. `test_get_db_uses_parameterized_query` — `with get_db() as conn: conn.execute("INSERT INTO prediction_log(city, predicted_price, predicted_range_low, predicted_range_high) VALUES (?,?,?,?)", ("Gurgaon", 1.0, 0.5, 1.5))` then `SELECT` round-trips. This is a behavioral test, not an internal-string-matching test (per testing skill).
8. `test_db_path_is_configurable` — set `APP_DB_PATH=tmp/x.db` via env, call `init_db()`, assert file exists at that path and `APP_DB_PATH` from config reflects it.
9. `test_css_has_no_hardcoded_hex` — read `app/static/css/*.css`, strip the `:root { ... }` token block, assert no `#[0-9a-fA-F]{3,6}` matches.
10. `test_landing_template_no_hardcoded_hex` — same regex scan over `landing.html`.
11. `test_conftest_fixtures` — sanity check `tmp_clean_db`, `app_client`, `api_client` all yield working objects (used by tests above; this one makes their failure mode explicit).

## How to apply (Ponytail honesty)

**Skipped / deferred, on purpose:**
- An actual FastAPI lifespan context manager instead of `@app.on_event("startup")` — the `on_event` decorator is deprecated in FastAPI 0.111+, but the spec's "minimal code that works" rule (Ponytail ladder rung 4 → 6) calls for the simpler version here. Later specs can lift this to `lifespan` if/when they add real startup work.
- A real logging setup. `print()` in `init_db()` failures is enough for Step 01 — `logging` config arrives with the pipeline work in spec 02.
- A `flask --app app:create_app run` shortcut. `python -m app.app` works; CLI alias is `nice to have`, not a blocker for "definition of done" §2.
- Migrating every existing test stub (`tests/test_price_prediction.py` etc.) from 0 bytes to placeholder — out of scope for Step 01; their own specs do that.
- A `Dockerfile` or any deploy scaffolding — Week 7, spec 07.

**Add these later, not now:**
- Real Flask error pages — when the first spec that actually 404s (`/predict`) lands.
- A `make pipeline` target — when there's something to `make` (spec 02 stages).
- A Sphinx / mkdocs doc build — out of scope per doc-freeze rule.
